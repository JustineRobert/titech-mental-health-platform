# Contributing

Prefer small, reviewable changes. Repository truth comes before architecture diagrams.

For each change:

1. Inspect current consumers and tests.
2. Implement in the existing canonical module.
3. Add unit/integration tests.
4. Review security and privacy impact.
5. Update documentation/status.
6. Run lint/tests/build where applicable.

Do not create `v2`, `new`, or parallel architectures without an explicitly documented migration reason.
